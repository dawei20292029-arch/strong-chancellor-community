# 决策协议

这些协议是后台检查表，不是要求用户逐项填写的表单。一次任务最多展开三个；能用较少协议闭环，就不要增加复杂度。

## 通用证据标签

- `事实`：由用户材料、系统状态或可靠来源直接支持。
- `推断`：从事实推导，必须说明推导链。
- `假设`：当前无法确认，但方案暂时依赖它。
- `待补证据`：会显著改变结论，需后续核验。
- `候选规则`：由一次或少量案例提出，尚未成为稳定规则。

## SC-01 对象-状态-目标

**适用**：需求模糊、目标反复变化、团队对“完成”的理解不一致。

**检查**：

1. 对象是什么，边界到哪里；
2. 哪些状态可观察，哪些只是主观描述；
3. 输入、输出和外部扰动分别是什么；
4. 目标是否可验证，约束是否真实；
5. 是否把代理指标误当最终结果。

**最小产物**：

```text
对象：
当前状态：
目标状态：
主指标：
约束/扰动：
完成条件：
```

**警报**：同时追逐互相冲突的目标；指标只能证明“忙过”，不能证明“有效”。

## SC-02 结构-反馈-延迟

**适用**：同类问题反复出现、越努力越糟、短期改善后反弹。

**检查**：

1. 哪些存量正在积累，例如任务、知识、债务、信任；
2. 哪些流入和流出改变存量；
3. 哪个增强回路放大结果，哪个调节回路限制结果；
4. 决策到结果之间有多长延迟；
5. 当前动作是在改参数，还是在改规则、反馈或目标。

**最小产物**：一条因果链、一个关键延迟、一个优先干预点。

**警报**：把延迟误判为无效而频繁换方向；用加速输入解决出口堵塞。

## SC-03 稳定-噪声-过滤

**适用**：数据很多但判断更差、指标剧烈波动、系统频繁改策略。

**检查**：

1. 信号是什么，噪声是什么；
2. 采样周期是否匹配业务变化速度；
3. 单次异常是否被误当趋势；
4. 修正力度是否过大，是否因延迟导致振荡；
5. 过滤是否抹掉了真正的边缘信号。

**最小产物**：主信号、过滤规则、观察窗口、修正上限。

**警报**：每出现一次负反馈就重构系统；只保留支持既有判断的数据。

## SC-04 分布式协同-权限

**适用**：多人、多部门或多 Agent 协作；中央节点成为瓶颈；角色越权或互相等待。

**检查**：

1. 哪些决策必须集中，哪些可以局部自治；
2. 每个节点接收什么、产出什么、向谁反馈；
3. 权限与责任是否匹配；
4. 冲突由谁裁决，何时升级；
5. 局部节点失联时系统能否继续运行。

**最小产物**：责任表、接口契约、升级条件、总控保留权。

**警报**：总控亲自处理所有细节；Agent 可以扩大权限却没有可审计记录。

## SC-05 容错-备用-回滚

**适用**：关键业务依赖单点；错误会级联扩散；变更后难以恢复。

**检查**：

1. 最可能失败的关键节点是什么；
2. 失败能否被及时检测和隔离；
3. 是否有降级模式、备用路径或人工接管；
4. 回滚点和恢复时间是否明确；
5. 冗余是否真的独立，还是共享同一故障源。

**最小产物**：故障信号、隔离动作、备用路径、回滚条件。

**警报**：备份从未演练；两个“独立”方案实际依赖同一供应商、模型或数据源。

## SC-06 最小实验-复盘-进化

**适用**：不确定性高、团队长期争论、准备投入较大资源但因果关系未验证。

**检查**：

1. 当前最值钱且最脆弱的假设是什么；
2. 最小实验能否在较短周期内推翻或支持它；
3. 成功、失败和停止条件能否事先写清；
4. 哪些变量需要固定，避免一次改变太多；
5. 结果如何进入下一轮，而不是停在复盘文档里。

**最小产物**：假设、实验、指标、时间窗、停止条件、下一轮规则。

**警报**：实验只允许成功解释；一次案例直接升级为永久规则。

## 协议组合

常用组合只有三种：

- 新项目：`SC-01 + SC-06`；
- 反复失控的流程：`SC-02 + SC-03 + SC-05`；
- 多 Agent 或跨团队系统：`SC-01 + SC-04 + SC-05`。

组合只是起点。真实现象与组合不符时，以证据为准。
